# Разметка 15 диалогов DEV с аргументацией

Оценивается только **оператор**. Бот и система — контекст. Номера в квадратных
скобках — номера реплик. Формат объяснения такой же, какой должна выдавать система:
ответ → доказательство → почему.

Обозначения: **Да / Нет / N/A** — для бинарных критериев; **0–20** (c04) и **0/4/7/10** (c06) —
ступени шкалы; c08 «Да» = грубая ошибка **есть**. ⚠ — спорно, нужна пометка «требует проверки».

## Правила, принятые при разметке

Их нужно перенести в описание критериев чек-листа, чтобы ИИ применял их так же.

1. **c02.** Можно было ответить по первым сообщениям клиента (с учётом чата с ботом) → N/A.
   Нельзя, и оператор уточнил → Да. Нельзя, и не уточнил или переспросил уже известное → Нет.
2. **c03 + c08.** Раскрытие данных счёта без идентификации → c03 = Нет **и** c08 = Да (⚠).
3. **c04.** Если вопрос клиента задан явно, а ответа на него нет, ступень не выше 10.
4. **c06 различает 7 и 4.** 7 — один неверный или неточный ответ, затем всё исправлено.
   4 — клиенту пришлось переспрашивать, потому что его вопрос проигнорировали или ответ не связан с вопросом.
   0 — противоречивые реплики. c06 оценивает только ясность, не правильность содержания.
5. **c07.** Вопрос решён и оператор попрощался → Да. Вопрос открыт и есть только прощание без итога
   или следующего шага → Нет. Оператор закрыл чат без прощания → Нет.
   Чат оборвал клиент → N/A.
6. **Бот — контекст.** Что клиент написал боту, оператор обязан знать (диалог 10).
